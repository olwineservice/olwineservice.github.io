# OL~ WINE Support Site

This repository hosts the GitHub Pages support site for OL~ WINE by OL Wine Service.

Published URL:

```text
https://olwineservice.github.io/
```

## Pages

- `index.html`: landing page
- `about.html`: product introduction
- `features.html`: bilingual overview of major app features
- `support.html`: user support and FAQ
- `privacy.html`: privacy policy, including optional anonymous data contribution
- `terms.html`: terms of use
- `account-deletion.html`: account and local data deletion guidance
- `open-source.html`: searchable full package/asset license notices and exchange-rate sources
- `licenses/<app-version>/NOTICES.txt`: versioned full-text notices
- `licenses/<app-version>/manifest.json`: app version, publication date, counts, and notice checksum
- `404.html`: not found page
- `FEATURE_SCREENSHOT_BRIEF.md`: feature order, capture inventory, and release checks

## Member account deletion revision (local draft, 2026-10-23)

The member/privacy/terms/support revision and external `account-deletion.html` flow are saved locally, not published or enabled. `account-deletion-config.js` defaults to disabled. The email request link remains available without scripts or an installed app. Member deletion and local wine/photo deletion are separate; no member identifier is added to label archives or contributions.

Before publishing, review the seller/jurisdiction-specific retention basis and separate recovery/transaction periods; do not assert a universal five-year requirement. Deploy the reviewed `myWineFridge/services/label_ai` lifecycle SQL/function/worker and test real provider revocation, queue completion, rejoining and refund behavior first. Replace only the public URL/publishable key in the config and enable it after verification. Never put service-role, OAuth client-secret, HMAC, encryption or worker keys in this repository. Add the exact HTTPS `https://olwineservice.github.io/account-deletion.html` callback (including permitted flow query matching) to the same project's Supabase Auth redirect allowlist. Backend CORS is limited to this fixed origin and member deletion routes; worker access never uses browser CORS.

Browser OAuth uses one-use PKCE in sessionStorage, removes callback parameters immediately, and keeps Auth/provider tokens in memory only while registering/revoking or requesting deletion. No third-party JavaScript is loaded. `node --test tests/account-deletion.test.mjs` runs with synthetic Auth/HTTP/DOM fixtures and no network or user deletion. Real OAuth and Pages publication remain release work. A support code or email alone never authorizes deletion/transfer. Support handles verified email requests and pending-token/Auth errors through the documented backend workflow.

## Updating Open Source Notices

The license page is generated by `tool/export_open_source_licenses.py` in the sibling `myWineFridge` app repository. Do not edit individual license bodies in the generated HTML. The 2026-10-22 revision was reviewed against paired unsigned release-mode builds from a fixed source snapshot, using AOT libraries, iOS native frameworks, Android R8/inline/resource evidence, and ABI-matched native libraries. It replaces the unfiltered 2026-10-07 inventory.

The page contains 68 groups and 69 notices. Its 173 names include package names, retained native modules, and supplier-notice bundles, not 173 direct app dependencies. Complete Flutter-engine and Google-SDK supplier notice bundles are separate linked text files; their internal component names are not all claimed as individually used by the app. Full text remains in `NOTICES.txt` as well. Google SDK access terms are distinguished from their bundled open-source notices.

For a new version or dependency/platform change, build matching iOS and Android release artifacts first. Generate a pending inventory, then review inclusion and notice-retention obligations against those artifacts. The app repository also contains `tool/audit_distribution_licenses.py`, `tool/license_runtime_inventory.init.gradle`, and the completed evidence in `docs/licenses/2026-10-22/`.

The low-level inventory command is:

```bash
python3 tool/export_open_source_licenses.py \
  --notices build/ios/iphoneos/Runner.app/Frameworks/App.framework/flutter_assets/NOTICES.Z \
  --inventory-out /tmp/olwine-license-review.json
```

Complete the review's platform/engine/native-SDK coverage, artifact paths and checksums, per-entry decisions and evidence, and additional required native/model notices. `scope_complete` must remain false while any of these are pending. Only then generate the replacement page:

```bash
python3 tool/export_open_source_licenses.py \
  --notices build/ios/iphoneos/Runner.app/Frameworks/App.framework/flutter_assets/NOTICES.Z \
  --review /path/to/completed-license-review.json \
  --site-dir ../olwineservice.github.io
```

Use the matching `--version` if the build overrides `pubspec.yaml`. The exporter adds bundled Unicode CLDR and Lucide/Feather notices. Native SDKs, the model, fonts, and supplier bundles require the completed additional-notice review. A `download_name` keeps a long supplier bundle accessible as a separate full-text link rather than expanding unrelated internal names into the main inventory. Do not add unrelated iso-codes, absent desktop/development components, or server-only SDKs. Do not remove a native component solely because its Dart package is a development dependency: `integration_test` native code is present in the audited iOS release. See `docs/SUPPORT_SITE_REVIEW.md` in the app repository. Commit only reviewed outputs. Existing version directories are preserved.
