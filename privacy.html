This policy describes on-device data, optional anonymous wine data contribution, and AI label recognition.

개인정보 처리방침

시행일: 2026-10-17

1. 적용 범위와 처리 주체

이 방침은 OL Wine Service가 제공하는 OL~ WINE 앱의 정보 처리 방식을 설명합니다. 앱은 사용자용 회원가입이나 이름·이메일·비밀번호 로그인을 제공하지 않지만, AI 라벨 인식 기능을 사용할 때에는 아래와 같이 Supabase의 익명 인증 사용자 ID와 서버 지갑을 사용합니다.

2. 기기에 저장되는 데이터

사용자가 입력한 와인, 셀러, 층·보관 위치, 구매·구매희망 정보, 시음 기록, 잔량, 메모, 사진, QR 라벨 정보, 앱 설정과 로딩 이미지는 원칙적으로 기기 내부 SQLite 데이터베이스와 앱 저장소에 보관됩니다. 처리되지 않은 앱 오류는 사용자 입력값을 제외한 오류 유형, 발생 경로와 정제된 스택을 최근 20건까지 기기 내부에 기록하며 서버로 자동 전송하지 않습니다.

카메라와 사진 접근은 와인·시음·셀러 사진, 로딩 이미지, QR 스캔과 AI 라벨 인식용 사진을 선택하거나 촬영할 때 사용됩니다. 사용자가 촬영 사진의 사진 보관함 저장을 켠 경우 사진 추가 권한도 사용됩니다.

3. 백업, CSV와 사용자 공유

사용자가 직접 실행하는 통합 CSV 내보내기에는 와인·시음 기록, 메모, 구매 정보와 와인별 보관 위치가 포함될 수 있으나 사진 파일과 셀러 구조·앱 설정은 포함되지 않습니다. 수동 전체 백업에는 로컬 데이터베이스, 설정과 사용자가 선택한 사진·로딩 이미지가 포함될 수 있습니다. 생성된 파일의 저장, 공유, 보관과 삭제는 사용자가 선택한 저장 위치와 공유 대상의 정책을 따릅니다.

CSV와 전체 백업에는 익명 데이터 제공용 비밀 토큰, AI 익명 인증 토큰, AI 지갑 잔액이나 지급·차감 내역을 포함하지 않습니다. 앱 데이터 복구는 서버의 AI 지갑이나 익명 인증 상태를 복구하거나 되돌리는 기능이 아닙니다.

4. 선택적 익명 와인·시음 데이터 제공

사용자가 이 기능에 별도로 동의하면 일부 와인·시음 정보를 서비스 개선과 향후 와인 관련 기능 개발을 위한 비식별 데이터로 OL Wine Service에 제공합니다. 이 동의는 AI 라벨 사진 전송에 대한 동의가 아니며 두 기능의 데이터 경로는 분리되어 있습니다.

와인 정보에는 기록별 서버 UUID, 와인명, 생산자, 빈티지, 종류, 품종, 생산 국가·지역, 구입일, 가격, 통화, 병 용량, 사용자가 동의 과정에서 선택한 국가·지역이 포함될 수 있습니다. 시음 정보에는 기록별 서버 UUID, 연결된 와인의 서버 UUID, 시음일시와 평점이 포함될 수 있습니다. 기록 UUID는 해당 와인과 시음의 수정·삭제 권한을 관리하고 두 기록을 연결하기 위한 값입니다. 서로 다른 와인을 한 사용자의 기록으로 묶는 계정 ID가 아니며 AI 익명 사용자 ID·지갑과 연결하지 않습니다.

사진, 개인 메모, 구입처, 셀러·층·보관 위치, 잔량·마신 양, 이름, 이메일, 전화번호, Apple·Google 계정 ID, AI 사용자 ID, 기기 ID와 광고 ID는 이 선택적 제공 경로로 전송하지 않습니다. 전송 시 기록별 임의 비밀 토큰을 사용하고 서버에는 그 SHA-256 해시만 별도 권한 정보로 저장합니다.

동의 여부는 무료·유료 기능에 영향을 주지 않으며 이 기능은 백업이나 기기 간 동기화가 아닙니다. 최초 동의 후 새로 추가·변경하는 대상만 전송합니다. 재동의 시 미동의 기간의 기존 기록을 함께 제공할지 사용자가 선택하며 기본값은 미포함입니다.

설정에서 동의를 철회하면 이후 새 전송을 중단하지만 이미 제공된 행은 유지됩니다. 동의가 활성화되고 기록별 비밀 토큰이 남아 있는 상태에서 앱의 와인·시음 기록을 삭제하면 서버 삭제 작업을 전송합니다. 전송이 완료되기 전에 앱을 삭제하거나 토큰을 잃으면 과거 서버 행을 자동으로 찾아 수정·삭제할 수 없습니다.

5. AI 라벨 인식, 익명 인증과 크레딧

사용자가 라벨로 자동 입력을 선택하고 라벨 영역을 확정하면 앱은 선택 영역을 긴 변 최대 1500픽셀의 JPEG로 만들고 EXIF, ICC 프로필과 텍스트 메타데이터를 제거합니다. 이 처리된 JPEG와 SHA-256 사진 해시를 HTTPS로 OL Wine Service의 Supabase 인식 서버에 전송합니다. 사용자가 영역 선택을 취소하면 사진을 전송하거나 AI를 호출하지 않습니다.

AI 기능의 첫 요청에서는 사용자용 가입 화면 없이 Supabase 익명 인증 사용자 ID를 생성합니다. 액세스 토큰, 갱신 토큰, 만료 시각과 익명 사용자 ID는 운영체제의 암호화 저장소에 보관됩니다. 실명, 이메일과 비밀번호를 받지 않는다는 의미이며, 서버가 동일한 익명 사용자의 AI 요청과 크레딧 사용을 계속 연결하지 않는다는 의미는 아닙니다.

Supabase에는 비공개 저장소의 전송 JPEG, 사진 해시와 요청 캐시 키, Gemini 원문 응답, 구조화된 와인 정보, 모델·프롬프트 버전, 처리 상태, 캐시 사용 여부, 토큰 사용량·비용과 처리 시간 같은 운영 메타데이터가 저장됩니다. 사용자 ID는 지갑 ID에 연결되고, 지갑의 요청 기록은 캐시 키를 통해 AI 결과·사진 해시·사진 파일과 연결될 수 있습니다. 서버 지갑은 사용 가능량, 보류량, 지급, 예약, 차감·해제, 요청 상태와 중복 처리 방지 장부를 관리합니다.

동일한 JPEG의 성공 결과가 있으면 추가 Gemini 호출 없이 캐시를 재사용할 수 있습니다. 사진 해시만 제출해서 다른 사용자의 결과를 조회할 수는 없으며, 사용자가 동일한 JPEG를 실제로 제출하고 서버 검증을 통과한 경우 캐시를 재사용합니다. 앱은 인식 결과 중 와인명, 라벨에서 읽힌 빈티지, 종류, 생산자, 품종, 국가와 지역을 돌려받습니다. 사용자가 이후 수정한 초안이나 최종 저장값은 AI 서버에 다시 전송하지 않습니다.

6. Google Gemini 처리

캐시에 결과가 없으면 OL Wine Service 서버가 처리된 JPEG와 인식 지시문을 Google Gemini API에 전송하고 응답을 받습니다. 현재 연결된 프로젝트는 활성 결제 계정이 있는 Gemini API 유료 서비스(Tier 1)를 사용합니다. Google의 Gemini API 추가 약관에 따르면 유료 서비스에 제출한 프롬프트, 이미지 같은 파일과 응답은 Google 제품 개선에 사용되지 않습니다.

다만 Google은 금지된 사용의 탐지·방지, 서비스 안전·보안과 법적 의무를 위해 프롬프트, 추가 문맥과 출력을 55일 동안 기록할 수 있습니다. 자동 시스템이 악용 여부를 검사하며, 의심 활동으로 표시된 경우 권한 있는 담당자가 검토할 수 있습니다. 자세한 내용은 Google의 Gemini API 악용 모니터링 안내에서 확인할 수 있습니다. 토큰 수, 운영 상태, 안전 필터 작동, 오류, 인증 정보, 성능 지표, IP 주소 등 서비스 운영에 필요한 사용·기술 정보도 Google의 관련 약관과 개인정보처리방침에 따라 처리될 수 있습니다.

7. 결제와 구매 복원

프리미엄 구매, 환불과 구매 복원은 Apple App Store 또는 Google Play에서 처리합니다. OL Wine Service는 카드 번호나 은행 계좌 같은 결제 수단 정보를 직접 받지 않습니다. 앱은 유료 기능 제공과 복원에 필요한 상품 식별자, 구매 상태와 거래 정보를 처리할 수 있습니다. AI 크레딧의 구매 지급과 광고 보상은 아직 확정·구현된 기능으로 설명하지 않습니다.

8. 처리업체, 전송과 접근 통제

OL Wine Service는 서버 인증, Edge Function, 비공개 파일 저장소와 PostgreSQL 데이터베이스 운영에 Supabase를 사용하고, 라벨 사진 인식에 Google Gemini API를 사용합니다. Supabase의 처리 역할과 국외 이전·하위처리자 정보는 데이터 위치 및 이전 안내와 법률 문서에서 확인할 수 있습니다. Apple과 Google은 스토어 결제·복원 기능을 각자의 정책에 따라 처리합니다.

앱과 서버, 서버와 처리업체 사이의 전송에는 HTTPS/TLS를 사용합니다. 이는 전송 구간 암호화이며 종단간 암호화가 아닙니다. 서비스 운영에 필요한 권한을 가진 OL Wine Service와 처리업체가 저장 데이터에 접근할 수 있습니다. AI 사진 저장소와 관련 테이블은 공개 접근을 허용하지 않고 서버 권한으로만 접근하며, 익명 인증 사용자가 지갑·장부·정책 테이블을 직접 조회하거나 변경하지 못하도록 제한합니다.

Supabase와 Google의 인프라 운영 과정에서 IP 주소, user-agent, 인증 정보, 요청 시각과 오류 같은 기술 로그가 보안, 장애 대응과 악용 방지를 위해 처리될 수 있습니다. 정확한 처리 국가는 각 서비스의 인프라와 운영 설정에 따라 달라질 수 있습니다. 확인되지 않은 특정 국가나 단일 리전을 이 방침에서 확정하지 않습니다.

9. 분석, 광고와 추적

OL~ WINE은 행동 분석 SDK, 광고 SDK 또는 원격 오류 수집 SDK를 사용하지 않습니다. 서버의 AI 요청·크레딧 기록과 기술 로그는 기능 제공, 정산, 보안과 장애 대응을 위해 처리하며 광고 프로필 작성이나 다른 회사의 앱·웹사이트 활동과 결합한 추적에 사용하지 않습니다. OL Wine Service는 앱에서 처리한 데이터를 판매하지 않습니다.

10. 보관과 삭제

기기 내부 데이터는 사용자가 앱에서 삭제하거나 앱을 삭제할 때까지 보관됩니다. 별도 위치에 저장한 백업, CSV와 공유 파일은 사용자가 직접 삭제해야 합니다.

익명 와인·시음 기여 행은 서비스 개선 목적에 필요한 동안 보관합니다. 위 4항의 조건을 충족한 앱 내 기록 삭제는 서버 삭제를 전송하지만 동의 철회나 앱 삭제만으로 이미 제공된 행이 삭제되지는 않습니다. 삭제된 기여 행의 기록별 권한 해시는 재점유와 재전송 악용을 막기 위한 tombstone으로 유지됩니다.

현재 AI 서버에는 사진, 인식 원문·결과, 익명 인증 사용자, 지갑, 지급·차감 장부와 요청 기록을 정해진 기간 후 자동 삭제하는 기능이 없습니다. 앱에서 로컬 사진을 삭제하거나 앱을 삭제하거나 익명 와인 데이터 제공 동의를 철회해도 이 AI 서버 데이터는 자동 삭제되지 않습니다. 지갑 장부와 지급 기록은 중복 지급·차감 방지와 정산 무결성을 위해 수정·삭제가 제한된 구조입니다.

서버 데이터 삭제 문의는 아래 이메일로 접수할 수 있습니다. 다만 앱에는 현재 AI 익명 사용자와 서버 사진·결과를 직접 조회하거나 삭제하는 화면이 없고, 요청자 확인 방법과 삭제 가능한 범위·예외의 운영 절차도 최종 확정 전입니다. 서버 백업에 남는 기간도 실제 운영 설정이 확인되지 않아 특정 기간을 약속하지 않습니다.

11. 아동 개인정보

OL~ WINE은 아동을 대상으로 하지 않으며 아동의 개인정보를 의도적으로 수집하지 않습니다.

처리 기능이나 업체, 보관·삭제 방식이 변경되면 이 방침과 시행일을 갱신합니다. 개인정보 관련 문의와 서버 데이터 삭제 문의는 olwine.service@gmail.com으로 보내주세요.

Privacy Policy

Effective date: 2026-10-17

1. Scope and controller

This policy explains how OL Wine Service handles information in the OL~ WINE app. The app does not offer user-facing sign-up or name, email, and password login. However, when AI label recognition is used, it uses a Supabase anonymous authentication user ID and a server-side wallet as described below.

2. Data stored on the device

User-entered wines, cellars, layers and storage locations, purchase and wishlist information, tasting records, remaining amounts, notes, photos, QR label information, app settings, and loading images are generally stored in the on-device SQLite database and app storage. For unhandled app errors, the app keeps up to 20 recent entries containing the error type, code path, and sanitized stack without user-entered values. These logs are not automatically sent to a server.

Camera and photo access is used when the user captures or selects wine, tasting, or cellar photos, loading images, QR scans, or a photo for AI label recognition. Photo-library add permission is used when the user enables saving captured photos to the photo library.

3. Backups, CSV, and user-directed sharing

A combined CSV export may include wine and tasting records, notes, purchase information, and each wine's storage location, but it does not include photo files, the cellar structure, or app settings. A manual full backup may include the local database, settings, and user-selected photos and loading image. Storage, sharing, retention, and deletion of generated files follow the locations and recipients chosen by the user.

CSV and full backups do not include anonymous-contribution secret tokens, AI anonymous authentication tokens, AI wallet balances, or credit grant and debit history. Restoring app data does not restore or roll back the server-side AI wallet or anonymous authentication state.

4. Optional anonymous wine and tasting contribution

If the user separately opts in, selected wine and tasting information is contributed in de-identified form to OL Wine Service for service improvement and future wine-related features. This consent does not cover transmission of AI label photos. The two features use separate data paths.

Wine information may include a per-record server UUID, wine name, producer, vintage, type, variety, production country and region, purchase date, price, currency, bottle size, and the country and region selected by the user during consent. Tasting information may include a per-record server UUID, the related wine's server UUID, tasting date and time, and rating. Record UUIDs manage update and deletion authority for a wine or tasting and connect those two records. They are not an account ID that groups different wines as belonging to one user, and they are not linked to the AI anonymous user ID or wallet.

Photos, personal notes, purchase place, cellar, layer or storage location, remaining or consumed amount, name, email address, phone number, Apple or Google account ID, AI user ID, device ID, and advertising ID are not transmitted through this optional contribution path. A random per-record secret token is used for transmission, and only its SHA-256 hash is stored in a separate authorization table on the server.

Consent does not affect free or paid features, and this feature is not backup or cross-device synchronization. After initial consent, only eligible records added or changed afterward are sent. On re-consent, the user chooses whether to include records from the period without consent; the default is not to include them.

Withdrawing consent in Settings stops future transmissions but does not remove rows already contributed. While consent is active and the per-record secret token remains available, deleting a wine or tasting record in the app sends a server deletion operation. If the app is deleted or the token is lost before transmission completes, the earlier server row cannot be located automatically for update or deletion.

5. AI label recognition, anonymous authentication, and credits

When the user chooses Fill from label and confirms the label area, the app creates a JPEG with a maximum long edge of 1500 pixels and removes EXIF, ICC profile, and text metadata. This processed JPEG and its SHA-256 image hash are sent over HTTPS to the OL Wine Service recognition server on Supabase. Canceling label-area selection sends no photo and makes no AI request.

On the first AI request, the app creates a Supabase anonymous authentication user ID without a user-facing sign-up screen. The access token, refresh token, expiry, and anonymous user ID are stored in encrypted operating-system storage. This means that OL Wine Service does not receive a real name, email address, or password for this account. It does not mean that the server cannot connect later AI requests and credit usage to the same anonymous user.

Supabase stores the transmitted JPEG in a private bucket, along with the image hash and request cache key, the raw Gemini response, structured wine information, model and prompt versions, processing status, cache status, token usage and cost, and processing-time metadata. The user ID is linked to a wallet ID, and wallet request records can be linked through a cache key to the AI result, image hash, and image file. The server wallet manages available and held balances, grants, reservations, debits and releases, request status, and an idempotent ledger.

If the same JPEG already has a successful result, the cache may be reused without another Gemini call. An image hash alone cannot retrieve another user's result; cache reuse occurs after the same JPEG is actually submitted and validated. The app receives wine name, vintage read from the label, type, producer, variety, country, and region. Edits the user later makes to the draft or final saved values are not sent back to the AI server.

6. Google Gemini processing

When no cached result exists, the OL Wine Service server sends the processed JPEG and recognition instructions to the Google Gemini API and receives the response. The currently connected project uses a Gemini API Paid Service with an active billing account at Tier 1. Under the Gemini API Additional Terms, prompts, files such as images, and responses submitted to Paid Services are not used to improve Google's products.

Google may nevertheless log prompts, additional context, and outputs for 55 days to detect and prevent prohibited use, maintain service safety and security, and meet legal obligations. Automated systems check for abuse, and authorized personnel may review content flagged for suspicious activity. More detail is available in Google's Gemini API abuse-monitoring guidance. Service-operation data such as token counts, operational status, safety-filter triggers, errors, authentication information, performance metrics, and IP addresses may also be processed under Google's applicable terms and privacy policy.

During operation of Supabase and Google infrastructure, technical logs such as IP address, user-agent, authentication information, request time, and errors may be processed for security, incident response, and abuse prevention. 10. Retention and deletion

On-device data remains until the user deletes it in the app or deletes the app. The user must separately delete backups, CSV files, and shared files stored elsewhere.

Anonymous wine and tasting contribution rows are retained while needed for the service-improvement purposes above. An in-app record deletion that meets the conditions in Section 4 sends a server deletion operation, but withdrawing consent or deleting the app does not itself delete previously contributed rows. The per-record authorization hash for a deleted contribution is retained as a tombstone to prevent takeover and replay.

The current AI server has no automatic fixed-period deletion for photos, raw and structured recognition results, anonymous authentication users, wallets, grants and debit ledgers, or request records. Deleting a local photo, deleting the app, or withdrawing anonymous wine-data contribution consent does not automatically delete this AI server data. Wallet ledger and grant records are structurally restricted from update and deletion to preserve accounting integrity and prevent duplicate grants or debits.

Server-data deletion inquiries may be sent to the email below. The app currently has no screen for directly viewing or deleting the AI anonymous user, server photos, or recognition results, and the operating procedure for verifying the requester and determining deletable scope and exceptions has not been finalized. The period for which deleted server data may remain in backups has also not been verified, so this policy does not promise a specific backup-deletion period.
